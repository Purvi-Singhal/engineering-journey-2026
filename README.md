## 8. Daily Workflow & Streak Protocol

To ensure continuous, accountable progress and maintain a healthy GitHub contribution streak:

1. **Daily Increments**: Every day of active study or coding ends with a tested code sample, problem solution, or technical writeup.
2. **Conventional Commits**: Commit messages strictly follow standard conventions:
   - `feat:` New concept implementation, project feature, or problem solution.
   - `docs:` Documentation, conceptual notes, or weekly reviews.
   - `refactor:` Code improvements, restructuring, or optimization.
   - `test:` Adding unit tests or test cases.
   - `fix:` Debugging or correcting previous implementations.
3. **No Fluff**: Commits must represent genuine learning output, working code, or technical reflections.

## 9. Learning Philosophy

```text
Learn → Practice → Explain → Recall → Master
```

Completing a tutorial or reading documentation does not equal mastery. This repository emphasizes **evidence of ability** through independently written code, tested projects, rigorous problem solving, and technical explanations.

- **Learn**: Absorb concepts from first principles.
- **Practice**: Build real implementations without relying on copy-paste code.
- **Explain**: Document the "why" and "how" in structured notes.
- **Recall**: Revisit and solve problems periodically to reinforce knowledge.
- **Master**: Integrate learned patterns into larger, resilient systems.

## 10. Engineering Principles

- Build more than I consume.
- Understand before copying.
- Prefer consistency over intensity.
- Write meaningful commits.
- Document important decisions.
- Debug before asking for the answer.
- Revisit forgotten concepts.
- Improve through iteration.
- Keep projects reproducible.
- Write code that another developer can understand.
